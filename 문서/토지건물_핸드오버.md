## 2. 화면 구조 (6단계)

좌측에 **고정 요약 사이드바**(접수번호·소재지·기준시점·토지단가·토지감정평가액·건물가액·감정평가액), 상단에 6개 탭.
탭 순서는 **산출근거 문서의 목차와 동일**합니다.

```
[좌측 요약 패널 · 상시 고정]
─────────────────────────────────────────────────────────────
대상물건 │ 공시지가기준법 │ 거래사례비교법 │ 토지감정평가액 결정 │ 건물 평가 │ 토지건물 시산가액
─────────────────────────────────────────────────────────────
```

### ① 대상물건
- **좌**: 감정평가 개요(접수번호·의뢰인·평가목적·기준시점·공시기준일 등 16개 입력)
- **우**: 본건 토지(여러 필지) / 본건 건물(표제부 + 층별개요)

### ② 공시지가기준법 — 가장 복잡한 화면
- **좌(계산 본류)**: 비교표준지 → 시점수정(지가변동률) → 개별요인비교(본건/표준지)
- **우(사례·보정)**: 서브탭 3개 — 거래사례 / 평가사례 / 그 밖의 요인
- **하단 고정 패널**: 시산가액 — 좌/우 어느 값을 만지든 **실시간 갱신**

### ③ 거래사례비교법
②에서 입력한 거래사례를 **재사용**(재입력 없음). 채택 → 사정보정·시점수정·요인비교 → 시산가액

### ④ 토지감정평가액 결정
두 시산가액 비교(차이 % 자동) → 채택 → 검토·결정의견

### ⑤ 건물 평가
①에서 불러온 층별개요를 이어받아 **재조달원가만 입력**하면 경과연수·잔가율·금액 자동

### ⑥ 토지건물 시산가액
토지+건물 합산, 결정의견, **검산 패널**(모든 산식 재계산 표시), 문서 생성 버튼(미연결)

## 3. 디자인 규칙 (중요 — 이대로 유지해주세요)

집합건물 앱과 통일된 토큰을 씁니다.

```
주색(pri)   #1a2744   강조(acc) #2563eb   테두리 #e2e5ea   표머리 #f0f2f5
배경        #f5f6f8   폰트: 맑은 고딕 13px
```

**값의 성격은 색 두 가지로만 구분합니다. 이 규칙을 지켜주세요.**

| 클래스 | 색 | 의미 |
|---|---|---|
| `.calc-c` | 회색 `#eef2f7` + 굵게 | **앱이 계산한 값** (손댈 수 없음) |
| `.jud-c` | 연한 노랑 `#fff9e6` | **평가사가 정하는 값** (손대는 칸) |

- 안내문(`.note`)은 **무채색**입니다 — 노란색이 "입력칸" 신호로만 쓰이도록 일부러 뺐습니다.
- 예전에 있던 `자동조회`·`판단`·`입력` 같은 **배지 라벨은 전부 제거**했습니다. 다시 넣지 마세요(사용자 요청).
- 표는 **문서(hwpx) 모양 그대로** 유지합니다. 2행 병합 헤더(`지목/이용상황` 등)도 문서와 같게 두는 게 검토에 유리합니다.
- **모든 표에 행 추가/삭제 버튼**이 있어야 합니다. 자동조회로 채워진 값도 **전부 직접 수정 가능**해야 합니다(사용자 요청: "자유도를 높혀야 해").

## 4. 데이터 모델

전역 배열 몇 개가 전부입니다. 프레임워크 없음.

```js
LANDS = [{ 소재지,지번,지목,면적,용도지역,이용상황,도로교통,형상,지세,공시지가,비고,
           pnu,                  // V-World 조회로 얻음 → 건축물대장 조회에 사용
           stdIdx,               // 적용 비교표준지 인덱스
           gf:[6],               // 개별요인(본건/표준지) 6조건
           gaf:[6],              // 개별요인(거래사례비교법) 6조건
           apply, gaApply }]     // 각 방식의 결정단가(반올림)

STDS  = [{ 소재지,지번,면적,지목,용도지역,형상,공시지가,이용상황,도로교통,지세,
           etcDecide }]          // 그 밖의 요인 결정 보정치(표준지별)

TRADES = [{ loc,use,jimok,landA,bldA,appr,struct,reCost,life,rest,total,date }]  // 거래사례
APPRS  = [{ no,loc,use,jimok,cond,unit,base,purp }]                              // 평가사례
ETC    = { type:'t'|'a', idx }   // 그밖의요인에 적용할 사례
GA     = { idx }                  // 거래사례비교법에 채택한 사례
BLD_STATE = { [층index]: {reCost, life} }   // 건물 층별 재조달원가·내용연수
```

**설계 원칙(합의된 것)**: **"개수는 지금, 항목은 나중"**
- 몇 개냐(리스트 구조)는 지금 확정 — 나중에 바꾸면 전면 재작업이라. 산출근거 문서 표에 `일련번호` 칸이 있어 문서 자체가 리스트 구조임.
- 무슨 값이냐(칼럼)는 나중에 추가 — 행 구조를 안 바꾸므로 저렴.
- **아직 미구현(의도적으로 미룸)**: 평가제외면적/평가대상면적/요인비교 구분면적, 동별 그룹핑·소계.

저장: `localStorage['tojigeonmul-v0.2']`에 폼 전체를 debounce 400ms로 자동 저장/복원.

## 5. 계산 로직 (검증 완료 — 함부로 바꾸지 마세요)

### 공시지가기준법 (필지별)
```
산출단가 = 표준지 공시지가 × 시점수정 × 지역요인 × 개별요인 × 그밖의요인
시산가액 = 결정단가(반올림) × 면적          // 필지별 → 합계
```
⚠️ 공시지가는 **대상토지 개별공시지가가 아니라 비교표준지 공시지가**입니다.

### 그 밖의 요인 (2단계 격차분석)
```
사례기준 표준지가액 = 사례단가 × 시점수정 × 지역요인 × 개별요인
표준지 현재가액     = 표준지 공시지가 × 시점수정
산출 비교치         = 앞 ÷ 뒤              // 결정 보정치는 평가사가 절사·조정
```

### 거래사례 토지 배분단가
```
건물 적용단가 = 재조달원가 × 잔존연수 / 내용연수
건물금액      = 건물 적용단가 × 건물면적
토지금액      = 총 거래금액 − 건물금액
토지단가      = 토지금액 ÷ 토지면적
```

### 건물 원가법
```
경과연수 = 기준시점 − 사용승인일 (자동)
잔가율   = (내용연수 − 경과연수) / 내용연수
금액     = 재조달원가 × 잔가율 × 면적       // 층별 → 합계
```

### 🔴 반올림 규칙 (실무 문서와 맞춘 것 — 중요)
**요인 곱셈의 계는 소수 3자리로 반올림한 뒤 다음 계산에 씁니다.**
예: 0.96 × 0.98 = 0.9408 → **0.941**로 반올림해서 사용.
이걸 안 하면 실무 문서와 값이 미세하게 어긋납니다. `mul()` 함수에 구현돼 있습니다.

## 6. 외부 연동 (전부 동작 확인됨)

| 데이터 | 소스 | 경로 | 상태 |
|---|---|---|---|
| 토지 특성·개별공시지가 | **V-World** | 브라우저 직접 호출 | ✅ 동작 |
| 비교표준지 | **V-World** | 브라우저 직접 호출 | ✅ 동작 |
| 건축물대장 표제부·층별개요 | **공공데이터포털 건축HUB** | Cloudflare Worker 경유 | ✅ 동작 |
| 지가변동률 | **부동산원 R-ONE** | Cloudflare Worker 경유 | ✅ 동작 |

### Cloudflare Worker (프록시)
- 주소: `https://ongyeol-proxy.woojin-apr.workers.dev`
- 코드: `문서/클라우드플레어_프록시.js` (수정 시 **Worker에 재붙여넣기 후 Deploy 필요**)
- 경로: `/bld?op=…&pnu=…` (건축물대장), `/rone?…` `/rone-list?…` (R-ONE)
- 키는 Worker의 Secret(`DATAGO_KEY`, `RONE_KEY`)에만 있고 페이지에 노출되지 않음
- 허용 출처: `wjjung111.github.io`

### 왜 프록시가 필요한가
공공데이터포털·R-ONE은 브라우저 직접 호출이 **CORS로 차단**됩니다. V-World는 안 막혀서 직접 호출합니다.

### 호출 폴백
`callApi()`가 **fetch → JSONP → 수동붙여넣기** 3단계로 자동 폴백하고, 호스트별로 성공한 방식을 기억합니다. 이 구조는 유지해주세요(정부 API가 불안정합니다).

### 키 메모
- V-World 키는 앱에 **내장**(평가사가 입력할 필요 없음). 도메인 잠금으로 보호. 개인 키로 override 가능.
- data.go.kr 개발키는 2028만료·일 10,000건. 운영 전환 시 운영키 신청 필요.

## 7. 붙여넣기 파서 (실무에서 제일 많이 쓰는 기능)

평가사는 사례를 **엑셀에서 복사**해 옵니다. 두 형식을 자동 판별해 필요한 칸만 뽑습니다.

- **실거래가**(거래사례): 머리글에 `물건금액`·`상세물건구분` 있으면 이 형식
- **KAPA HUB**(평가사례): 머리글에 `평가목적`·`감정평가총액` 있으면 이 형식

구현 포인트:
- **머리글 이름 기반 매핑**(칼럼 순서가 바뀌어도 동작). 위치 기반 아님.
- TSV 파서가 **따옴표 안 줄바꿈**을 처리합니다(엑셀 다중행 셀 대응). 이거 없으면 KAPA HUB가 깨집니다.
- 실거래가에 **토지면적이 없어서** 그 칸만 직접 입력해야 합니다(주구조·재조달원가·잔존연수도).

- 표 계산식(FORMULA) 필드: 캐시된 값이 남아 플레이스홀더를 덮어씀 → 템플릿에서 `fieldBegin/fieldEnd` 쌍 제거
- 꼬리말 낀 런 분리: 감싸는 런을 rfind로 찾으면 꼬리말 내부를 잘못 집음 → 여닫이 **스택**으로 탐색
- `linesegarray`(줄배치 캐시): 값 셀에 긴 토큰 넣으면 겹침. **값 셀만** 제거하고 본문 산문은 유지

## 10. 작업 시 주의사항

- 사용자는 **감정평가사**이고 코딩 전문가가 아닙니다. **한국말로, 결과 위주로** 설명하고 할 일은 숫자로 명시해주세요.
- 사용자는 **빠른 반복**을 선호합니다: 수정 → 머지 → 라이브 확인.
- **계산 결과는 문서와 1원까지 맞아야 합니다.** 코드 리뷰만으로는 검증되지 않으니 실제 숫자를 대조하세요.
- 평가사의 **판단 영역(사례 선정·요인 우열·최종 결정단가)은 자동화하지 않습니다.** 계산과 자료수집만 자동화합니다.
- 위험 작업(템플릿 교체·localStorage 키 변경·대규모 리팩토링)은 **사전 동의**를 받으세요.
- `localStorage` 키(`arap_*`, `exact-vworld-key` 등)는 **개명 금지** — 사용자 저장데이터가 끊깁니다.
